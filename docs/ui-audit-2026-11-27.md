# Production UI Audit — 27 November 2026

## Scope

Unauthenticated production experience at `https://research-and-blog-writer.onrender.com/`: sign-in, empty workspace, desktop layout, theme toggle, 390px mobile layout, mobile research drawer, and settings modal. No research run was started and no user data was submitted.

## Highest-priority findings

1. **P0 — Mobile layout has horizontal overflow.** At a 390px viewport, the document is 523px wide (client width 384px), and the header controls extend off-screen. Settings, AI Command Center, and Sign In are pushed beyond the visible width. Make the header responsive: keep one primary action visible and put secondary controls in an overflow menu; add `min-w-0`, avoid fixed combined widths, and prevent horizontal page overflow.
2. **P1 — Light theme state does not produce a light surface.** The UI displayed the same dark workspace before and after changing the theme state. This makes the theme label misleading and breaks the user's visual expectation. Remove hard-coded dark `slate-*` backgrounds/text from shared surfaces and consistently use semantic tokens.
3. **P1 — Mobile settings is cramped and leaves the underlying page exposed.** At 390px, Settings renders as a narrow, left-aligned panel while the rest of the page remains visible/off-canvas. Use a full-screen mobile dialog/sheet with a sticky close action and a single-column settings navigation.
4. **P1 — Empty state does not guide the first task strongly enough.** The centre says “No Article Selected”, while the creation controls are hidden in the left panel/drawer. On mobile, opening the research drawer is an additional discovery step. Add an obvious “Start research” primary CTA in the empty state that focuses/opens the topic input.
5. **P1 — Desktop information density is too high.** The initial workspace simultaneously presents a topic form, four suggestions, library/search, two centre tabs, empty state, metrics, two command-centre tabs, and four agent cards. This dilutes the main action. De-emphasize standby telemetry and collapse the command centre until a run begins.

## Accessibility and interaction risks

6. **P1 — Mobile drawer is not exposed as a dialog.** The opened drawer appears as a generic container in the accessibility tree, with no dialog semantics. Add `role="dialog"`, `aria-modal="true"`, a label, focus trap, focus return, and Escape-to-close.
7. **P2 — Icon-only mobile controls have incomplete accessible names.** The mobile research, API-key, and AI-command-centre controls rely on titles or icons rather than an explicit `aria-label`. Add explicit labels and `aria-expanded` to the two drawer triggers.
8. **P2 — Keyboard focus is inconsistent.** Most buttons do not have a visible `:focus-visible` treatment; inputs do. Use a shared `focus-visible` ring on all interactive controls.
9. **P2 — Delete action is hover-only.** Article delete is hidden until pointer hover, which is undiscoverable for keyboard and touch users. Keep it visible when the row has focus and add a confirmation/recovery pattern.
10. **P2 — Tabs are styled as buttons only.** Research Article/Visual Research System and command-centre views lack tab semantics (`role=tablist`, `role=tab`, `aria-selected`, linked tab panels).

## What works

- The sign-in dialog has a clear split layout, legible form labels, and a strong primary flow.
- Desktop grouping is visually consistent and the research topic form has a visible focus state.
- The agent panels communicate the multi-stage system clearly once a user understands the product.

## Audit steps

| Step | Surface | Health |
| --- | --- | --- |
| 1 | Sign-in dialog | Good visual structure; not tested with authentication. |
| 2 | Desktop empty workspace | Functional but over-dense and weak as a first-run experience. |
| 3 | Theme control | Needs correction; theme state and rendered appearance diverge. |
| 4 | 390px mobile workspace | Poor; confirmed 139px horizontal overflow. |
| 5 | Mobile research drawer | Usable visually, but lacks dialog/focus semantics. |
| 6 | Mobile settings | Poor; needs a dedicated full-screen mobile pattern. |

## Recommended implementation order

1. Fix mobile header overflow and convert settings to a mobile full-screen dialog/sheet.
2. Make theme tokens apply to every shared surface; add a visual regression check for both themes.
3. Add a prominent empty-state “Start research” path and simplify idle command-centre content.
4. Fix drawer/dialog, focus, labels, delete discoverability, and tab semantics.

## Evidence limits

Screenshots and live DOM/accessibility state were captured from production at desktop and 390px mobile widths. Authenticated article editing, API-key entry, actual research execution, generated article display, deletion confirmation, and screen-reader testing were intentionally not performed.
